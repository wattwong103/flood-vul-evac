## The one decision

**`population_version` does not identify the age-structured runs.** They record
`bkk-pop-v0.2-<aoi>-2020` because for named pilots the version comes from
`config/pilots/<aoi>.json`, which takes precedence over `config/population.json`.

To correct it: bump `versions.population` in four pilot configs, then re-stage
four pilots and re-run eight runs — roughly 45 minutes including pair audits.
`runner.py:284` binds staged cells to the bundle version, so this cannot be done
partially; bumping the config alone **breaks** the existing release.

The data in those runs is correct. Only the label is stale. Worth doing only if
the version string matters to your evidence chain.

## Reading the results

**Dry clearance times are not zero** — median 31.6 to 60.8 minutes, purely
evacuation distance with no flood. Any figure quoting the dry→moderate increase
must say it is a distance baseline plus flood impedance, or a reviewer will ask
what the dry number represents.

**The city baseline is stale, the four pilot areas are not.** The pilot AOIs were
re-staged on the admitted Geofabrik extract with boundary areas and geometry
hashes byte-identical to before, so only the network source moved.

## On the Japanese comparison

Pseudo-PFLOW has census per-person demographics, Markov+MNL behaviour tuned to
mode-share targets, R² = 0.81 against mobile-phone data, 130 M people, 500 m
mesh every ten minutes, freight truck/taxi and transit routing. Its cited
GitHub repo returns **404**; the dataset is JoRAS-on-application only.

BKK/FLOW is **not better as a mobility dataset**. It leads on evidence integrity
and on the flood/evacuation dimension Pseudo-PFLOW has no equivalent of. Say it
that way; a stronger claim will not survive review.

See `docs/PSEUDOPFLOW_COMPARISON.md` for the full gap analysis and
`data/curated/population/` for the age/sex marginals and checksums.
